HƯỚNG DẪN SỬ DỤNG
VATM AEROSYNC

Cài đặt, vận hành, xử lý dữ liệu và khắc phục sự cố

Phiên bản tài liệu: 1.0
Áp dụng từ bản AeroSync 0.0.1-20260826-180339
Ngày cập nhật: 27/08/2026

1. Mục đích và phạm vi

Tài liệu này hướng dẫn quản trị viên và người vận hành triển khai AeroSync trên Windows, cấu hình kết nối, theo dõi ba dịch vụ, tiếp nhận file từ email/thư mục, kiểm tra kết quả, xử lý file lỗi và thu thập thông tin khi cần hỗ trợ.

Phạm vi nghiệp vụ: AeroSync đọc phép bay từ email hoặc thư mục incoming, nhận diện hãng/format, trích xuất dữ liệu, đối chiếu từ điển ATFM và ghi phép bay vào cơ sở dữ liệu đích.

2. Tổng quan hệ thống

Thành phầnChức năng
AeroSyncApiCung cấp giao diện và API báo cáo, trạng thái, thao tác vận hành.
AeroSyncIngestĐọc email và file trong thư mục incoming, tạo công việc xử lý.
AeroSyncWorkerNhận công việc, đọc nội dung, kiểm tra nghiệp vụ và ghi dữ liệu ATFM.

3. Điều kiện trước khi cài đặt

  • Windows PowerShell 5.1 và tài khoản có quyền Administrator.
  • Java 21; không cần Maven hoặc Node.js trên máy chạy gói deploy.
  • Kết nối được Oracle, RabbitMQ cổng 5672 và Redis cổng 6379.
  • Cổng API, mặc định 8081, không bị ứng dụng khác sử dụng.
  • Có quyền đọc/ghi tại C:\AeroSync và các thư mục lưu file.
java -version
Test-NetConnection 192.168.131.15 -Port 1521
Test-NetConnection localhost -Port 5672
Test-NetConnection localhost -Port 6379
Get-NetTCPConnection -LocalPort 8081 -ErrorAction SilentlyContinue

4. Cài đặt hoặc cập nhật AeroSync

  1. Sao chép file ZIP deploy sang máy chủ và giải nén toàn bộ vào một thư mục tạm.
  2. Mở PowerShell bằng Run as administrator.
  3. Chạy kiểm tra trước deploy:
Set-Location 'D:\duong-dan-goi-deploy'
.\AeroSync-Deploy.cmd check

Chỉ tiếp tục khi không còn dòng đánh dấu [X]. Sau đó chạy:

.\AeroSync-Deploy.cmd

Script sẽ dừng các service đang chạy, sao lưu bản cũ, cập nhật chương trình, cài hoặc refresh service, khởi động lại và kiểm tra API.

Không xóa thủ công C:\AeroSync khi cập nhật. Thư mục này chứa cấu hình, log và bản sao lưu phục vụ rollback.

5. Cấu hình file môi trường

File cấu hình thật phải nằm tại C:\AeroSync\config\.env. Không sử dụng nhầm C:\AeroSync\config.env.

SPRING_DATASOURCE_URL=jdbc:oracle:thin:@//192.168.131.15:1521/DB19
SPRING_DATASOURCE_USERNAME=atfm
SPRING_DATASOURCE_PASSWORD=<mat-khau>
SPRING_JPA_HIBERNATE_DDL_AUTO=validate

APP_ATFM_DATASOURCE_URL=jdbc:oracle:thin:@//192.168.131.15:1521/DB19
APP_ATFM_DATASOURCE_USERNAME=atfm
APP_ATFM_DATASOURCE_PASSWORD=<mat-khau>

SPRING_RABBITMQ_HOST=localhost
SPRING_RABBITMQ_PORT=5672
SPRING_DATA_REDIS_HOST=localhost
SPRING_DATA_REDIS_PORT=6379
SERVER_PORT=8081

Bảo mật: Không ghi mật khẩu thật vào tài liệu, Git, ảnh chụp hoặc log gửi hỗ trợ. Tên biến dùng dấu gạch dưới bình thường, ví dụ SERVER_PORT, không viết SERVER\_PORT.

5.1. Cấu hình thư mục file

APP_FILE_PATHS_INCOMING=D:/vatm-storage/incoming
APP_FILE_PATHS_PROCESSED=D:/vatm-storage/processed
APP_FILE_PATHS_ERROR=D:/vatm-storage/error
APP_FILE_PATHS_QUARANTINE=D:/vatm-storage/quarantine
Thư mụcÝ nghĩa
incomingFile đầu vào đặt trực tiếp trên máy chủ.
processedFile đã xử lý hoàn tất.
errorFile lỗi kỹ thuật hoặc lỗi xử lý.
quarantineFile cần kiểm tra thủ công, thiếu format hoặc dữ liệu không chắc chắn.
error-formatNguồn tham khảo để bổ sung YAML cho format hãng chưa nhận diện.

5.2. Cấu hình email

APP_EMAIL_HOST=mail.vatm.vn
APP_EMAIL_PORT=993
APP_EMAIL_PROTOCOL=imaps
APP_EMAIL_USERNAME=<tai-khoan-email>
APP_EMAIL_PASSWORD=<mat-khau-email>
APP_EMAIL_FOLDER=INBOX
APP_EMAIL_PROCESSED_FOLDER=AeroSync/Processed
APP_EMAIL_ERROR_FOLDER=AeroSync/Error

Sau khi đổi file .env, phải restart ba service để cấu hình mới có hiệu lực.

6. Kiểm tra sau deploy và vận hành service

.\AeroSync-Deploy.cmd status
Get-Service AeroSyncApi,AeroSyncIngest,AeroSyncWorker
Invoke-WebRequest http://localhost:8081/api/dashboard/stats -UseBasicParsing
Get-Content C:\AeroSync\VERSION

Kết quả hợp lệ: cả ba service ở trạng thái Running, API trả về thành công và VERSION đúng với gói vừa cài.

LệnhCông dụng
AeroSync-Deploy.cmd checkKiểm tra môi trường, cấu hình, kết nối và service.
AeroSync-Deploy.cmd statusXem trạng thái bản cài và ba service.
AeroSync-Deploy.cmd restartKhởi động lại toàn bộ service.
AeroSync-Deploy.cmd rollbackKhôi phục bản sao lưu gần nhất khi bản mới lỗi.

7. Quy trình tiếp nhận và xử lý file

7.1. Nguồn email

  1. Gửi email có file đính kèm hợp lệ tới hộp thư đã cấu hình.
  2. Ingest đọc email, mỗi file đính kèm được theo dõi riêng.
  3. Worker nhận diện format, đọc phép bay, kiểm tra từ điển và ghi ATFM.
  4. Email/file thành công được chuyển sang thư mục Processed; file lỗi được chuyển Error hoặc Quarantine theo nguyên nhân.

Dữ liệu API có source_type=email và source_key=1.

7.2. Nguồn thư mục

  1. Sao chép file vào đúng thư mục D:\vatm-storage\incoming.
  2. Không mở hoặc ghi đè file khi ingest đang đọc.
  3. Chờ hết chu kỳ scheduler hoặc theo dõi giao diện.

Dữ liệu API có source_type=folder và source_key=2.

8. Cách đọc kết quả xử lý

Trạng tháiÝ nghĩa và thao tác
SAVED / SUCCESSĐã ghi dữ liệu. Vẫn cần đối chiếu số chuyến, chặng, giờ, tàu bay, via và remark với file gốc.
SKIPPEDTài liệu không phải phép bay, trùng hoặc thuộc trường hợp được phép bỏ qua. Đọc errorMessage để biết lý do cụ thể.
ERROR / FAILEDLỗi đọc file, cấu hình, kết nối hoặc nghiệp vụ. Sửa nguyên nhân trước khi gửi lại.
QUARANTINEDCần kiểm tra thủ công, thường do chưa có YAML, không chắc format hoặc thiếu phép gốc.
REVISION_REVIEWPhép sửa đổi chưa tìm thấy/đối chiếu được phép gốc hoặc không thể cập nhật an toàn.

9. Quy tắc dữ liệu nghiệp vụ chính

  • Phép đột xuất không đọc hoặc không đối chiếu được tàu bay: vẫn lưu, dùng loại dự phòng A000 và giữ errorMessage chi tiết.
  • Loại tàu bay bắt đầu bằng 3 được chuẩn hóa thêm A (321 thành A321, 32N thành A32N); bắt đầu bằng 7 thêm B (787 thành B787).
  • Đường bay nhiều dòng phải lấy theo từng sector; các đoạn đã xuất hiện không lặp lại.
  • Nếu không đối chiếu được via, giữ nội dung có ích trong trường via và ghi rõ nguyên nhân trong errorMessage.
  • Phép sửa đổi phải tìm đúng phép gốc, cập nhật chặng/ngày/giờ theo nội dung NEW và ghi remark dạng ngày xử lý + R(n).
  • Các quy tắc A000/nới lỏng lỗi tàu bay, đường bay chỉ áp dụng cho phép đột xuất nếu nghiệp vụ đã quy định; phép mùa vẫn kiểm tra nghiêm ngặt.

10. Gửi lại file lỗi

  1. Đọc errorMessage, mở file gốc và sửa đúng nguyên nhân.
  2. Kiểm tra file không bị hỏng, có bảng lịch bay, loại tàu bay, chặng, ngày/giờ và số phép.
  3. Gửi lại file qua hộp thư nhận dữ liệu hoặc đặt lại vào incoming.
  4. Theo dõi job mới và đối chiếu dữ liệu đích.

Retry/reset giữ nguyên syncJobId chỉ được thực hiện qua chức năng quản trị được thiết kế cho ERROR, SKIPPED, QUARANTINED và lỗi format. Không xóa trực tiếp dữ liệu ATFM nếu chưa xác định chính xác master/detail và phép gốc dùng chung.

11. Kiểm tra bằng API

$id = 29840
Invoke-RestMethod "http://localhost:8081/api/reports/emails/$id" |
  ConvertTo-Json -Depth 10

Kiểm tra các trường: processingStatus, jobStatus, syncJobId, permitNumber, attachmentName, errorMessage, source_type và source_key.

Nếu API trả 409 Conflict khi resend, không gửi lặp liên tục. Đọc nội dung phản hồi để xác định job đang xử lý, trạng thái không phù hợp hoặc bản ghi đích không thể reset an toàn.

13. Checklist vận hành hằng ngày

  • Ba service đều Running.
  • Oracle, RabbitMQ, Redis kết nối bình thường.
  • Không có file tồn bất thường trong incoming.
  • Kiểm tra ERROR, QUARANTINED, SKIPPED và errorMessage mới.
  • Đối chiếu ngẫu nhiên file thành công với DB: số chuyến, callsign, ngày, sân bay, giờ, craft, purpose, via và remark.
  • Kiểm tra dung lượng ổ đĩa và log tăng bất thường.

14. Thông tin cần gửi khi yêu cầu hỗ trợ

  • VERSION đang chạy.
  • ID email/job/syncJobId và tên file.
  • Trạng thái cùng errorMessage đầy đủ.
  • Log API/Ingest/Worker đúng khoảng thời gian xảy ra lỗi.
  • File nguồn lỗi nếu được phép chia sẻ.
  • Kết quả mong đợi và dữ liệu thực tế trong DB.

Trước khi gửi, phải che mật khẩu Oracle, mật khẩu email, token, dữ liệu cá nhân và các thông tin nhạy cảm.
