Tự động cập nhật dữ liệu từ email và thư mục lưu trữMục tiêu chức năng Sơ đồ phân rã chức năng/Luồng xử lý nghiệp vụ/Thông tin Use CaseSTTThành phầnNội dung chi tiết1Tác nhân tham gia• Job hệ thống (Bộ định thời hệ thống)• Email Server (IMAP/POP3/Exchange)• File System (Thư mục lưu trữ file mẫu)• Quản trị hệ thống (Admin cấu hình)• Người khai thác (Giám sát, xử lý ngoại lệ)2Mô tả chức năngHệ thống tự động quét định kỳ hộp thư điện tử và thư mục lưu trữ để phát hiện file dữ liệu mới, thực hiện validate định dạng, parse nội dung, cập nhật vào CSDL trung tâm, đồng thời lưu trữ bản gốc và ghi nhật ký kiểm toán. Dữ liệu lỗi được chuyển sang thư mục riêng và gửi cảnh báo để xử lý.3Tiền điều kiện• Thư mục nguồn/đích (incoming, processed, error) đã được cấp quyền• Tài khoản Email Server đã cấu hình (IMAP/SSL, whitelist sender)• Template file mẫu (CSV/XLSX/XML/JSON) và rule mapping trường đã được phê duyệt• Scheduler đã kích hoạt (mặc định: 5 phút/lần)• Kết nối CSDL Oracle ổn định4Hậu điều kiện• Dữ liệu mới được cập nhật vào CSDL (transaction atomicity)• File gốc lưu tại /processed/ với chuẩn SLB_YYYYMMDD_HHMMSS_<source>_<name>.ext• File lỗi chuyển sang /error/ kèm log chi tiết• Nhật ký kiểm toán ghi đầy đủ (who/when/what/result), lưu trữ ≥ 5 năm• Cảnh báo gửi đến Admin qua Dashboard nếu có lỗi5Luồng xử lý chínhBước 1: Scheduler kích hoạt quét Email Server và thư mục /data/incoming/Bước 2: Lấy danh sách email + phát hiện file mới Bước 3: Lưu metadata email và download attachment về thư mục tạmBước 4: Kiểm tra định dạng (extension, encoding UTF-8, schema, kích thước)Bước 5: Parse dữ liệu theo mapping template, chuẩn hóa (trim, uppercase, convert timezone)Bước 6: Kiểm tra nghiệp vụ (Callsign, From, To, DateFlight,…)Bước 7: Cập nhật vào Cơ sở dữ liệuBước 8: Di chuyển file sang /processed/, đánh dấu email READ, ghi log SYNC_SUCCESSBước 9: Gửi thông báo hoàn thành tới Dashboard6Các luồng thay thế• ALT-01 - File sai định dạng: Chuyển sang /error/, sinh file .log mô tả lỗi, cảnh báo WARNING• ALT-02 - Vi phạm rule nghiệp vụ: ROLLBACK transaction, chuyển file sang /quarantine/ để Operator review• ALT-03 - File trùng lặp (hash cũ): Bỏ qua, log SKIPPED_DUPLICATE, không ghi đè CSDL• ALT-04 - Mất kết nối CSDL: Retry 3 lần (exponential backoff 2-4-8 phút); nếu thất bại → log CRITICAL + Hiện cảnh báo cho Admin• ALT-05 - Email Server không khả dụng: Retry chu kỳ tiếp theo; alert sau 3 lần thất bại liên tiếp• ALT-06 - Email không có attachment: Parse body (nếu format cho phép), ngược lại log NO_ATTACHMENT7Quy tắc nghiệp vụ• BR-01 (Idempotency): Mỗi file xử lý duy nhất 1 lần, xác định bằng SHA-256 hash• BR-02 (Atomicity): Toàn bộ batch phải thành công hoặc ROLLBACK toàn bộ• BR-03 (Retention): /processed/ lưu 60 ngày; /error/ & /quarantine/ lưu 90 ngày• BR-04 (Security): Credentials mã hóa AES-256; kết nối TLS 1.2+; audit log write-once• BR-05 (Priority): File có keyword URGENT/VIP được ưu tiên trong queue• BR-06 (Rate Limit): Tối đa 100 file/chu kỳ để tránh quá tải• BR-07 (Audit): 100% thao tác được ghi log (timestamp, user, action, input, output, duration)  Giao diện người sử dụng///
