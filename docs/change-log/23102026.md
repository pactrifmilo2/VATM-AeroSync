## OF-7974 passenger revision profile selection

- Objective: prevent a passenger revision with OLD/NEW schedules from being parsed by the cargo scheduled profile.
- Files changed: `aerosync-worker/src/main/resources/permit-formats/caav-english-overflight-scheduled.yaml`, `aerosync-worker/src/main/resources/permit-formats/airline-generic-overflight-scheduled.yaml`, `aerosync-worker/src/test/java/vatm/aerosync/worker/pipeline/AirAsiaOverflightRevisionProfileTest.java`.
- Before/after: scheduled cargo profiles could match an `RVS` document with `Schedules: UTC Time` and default every row to `CAR`; they now require `CARGO FLIGHT` and reject explicit `REV`/`RVS` revisions. The generic revision profile parses the same passenger document as `PAX`.
- Verification: `mvn -pl aerosync-worker -am "-Dtest=AirAsiaOverflightRevisionProfileTest,CaavEnglishOverflightRevisionProfileTest" "-Dsurefire.failIfNoSpecifiedTests=false" test` passed: 3 tests run, 0 failures, 1 optional external-document test skipped.
- Result: the parser regression test confirms `OF-7974`-shaped OLD and NEW schedules select `airline-generic-overflight-revision` and produce six `PAX` rows.
- Remaining limitation: the quarantined runtime job was not retried; deployment and a controlled retry are still required to persist the revision into ATFM.
