# Change log 24102026

## OCR variants for CAAV permit YAML

- Objective: recognize the Numero sign (`№:`), Unicode whitespace in permit numbers such as `LD  -    72/A/W/2026VN`, and common OCR errors in aircraft/route table headers.
- Files changed: `aerosync-worker/src/main/resources/permit-formats/caav-english-issued-permit-revision.yaml`; CAAV generic landing/overflight issued and revision profiles; CAAV generic seasonal landing/overflight revision profiles; `CaavGenericOverflightAircraftTableTest.java`; `CaavSeasonalPermitOcrVariantTest.java`; `docs/plans/24102026-ocr-permit-yaml-variants.md`.
- Before/after behavior: selected CAAV permit patterns did not accept the Numero prefix; seasonal permit patterns did not enable Unicode whitespace matching. CAAV generic tables lacked variants for OCR-damaged labels such as `Aircrafl Type`, `Aircraft Registralion Mark`, `Setor`, and singular `Airway`. The profiles now support those cases while still requiring their semantic columns and values.
- Scope assumption: applied recommended option A as a default because the user continued requesting implementation without selecting an alternative. Changes are confined to the seven relevant CAAV profiles; unrelated airline-specific profiles were not bulk-edited. The generic label `Route` was not mapped to airway because that meaning is ambiguous.
- Verification: `mvn -pl aerosync-worker -am "-Dtest=CaavGenericOverflightAircraftTableTest,CaavSeasonalPermitOcrVariantTest,CaavEnglishIssuedPermitRevisionProfileTest,WordPermitFormatDetectorTest" "-Dsurefire.failIfNoSpecifiedTests=false" test`.
- Result: BUILD SUCCESS; 15 tests, 0 failures, 0 errors, 1 skipped (optional real-document sample-path test). Tests confirmed issued and seasonal permit numbers, the Numero prefix, NBSP/repeated spaces, and extraction of aircraft type, registration and airway from OCR-damaged headers.
- Limitation: OCR aliases cover explicit common header confusions, not arbitrary OCR corruption. Unreadable or ambiguous values still require review; no aircraft/route values are inferred. No corpus-wide replay/audit was run.
