# Nhật ký chỉnh sửa 19112026

## Khắc phục filter bỏ chuyến landing outbound

- **Mục tiêu:** Giữ các chuyến landing không mùa vụ có sân bay Việt Nam (VV*) ở đầu đi hoặc đầu đến, khắc phục job Incoming LD-4315 bị thiếu các chặng VVNB -> ZHEC.
- **File sửa:** `aerosync-worker/src/main/java/vatm/aerosync/worker/pipeline/LandingFlightFilter.java`; regression test tương ứng.
- **Trước:** Filter chỉ giữ chuyến có sân bay đến bắt đầu VV, làm loại chặng outbound từ Việt Nam.
- **Sau:** Filter giữ chuyến khi sân bay đi hoặc sân bay đến bắt đầu VV. Chuyến cả hai đầu ngoài Việt Nam vẫn bị loại; phép mùa vụ, phép khác loại và referenced-season không đổi.
- **Kiểm tra:** `LandingFlightFilterTest`: 3 tests, 0 failures/errors. Maven package worker thành công; deploy artifact: `aerosync-worker/target/aerosync-worker-0.0.1-SNAPSHOT-deploy.jar`.
- **Bằng chứng hồi quy:** Test gồm sáu dòng lịch LD-4315 và xác nhận bốn dòng có ít nhất một đầu VV được giữ, bao gồm VVNB -> ZHEC.
- **Triển khai:** Chưa deploy, không replay, không ghi Oracle/ATFM.

## Hướng dẫn build và triển khai lên server

1. Lấy commit chứa fix, chạy test filter và build worker:

   ```powershell
   mvn -pl aerosync-worker -am '-Dtest=LandingFlightFilterTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
   mvn -pl aerosync-worker -am -DskipTests package
   ```

2. Artifact worker standalone là `aerosync-worker/target/aerosync-worker-0.0.1-SNAPSHOT-deploy.jar`. Nếu dùng gói triển khai chính thức, build toàn bộ release bằng `scripts/release.ps1` (không dùng `-SkipBuild`) để tạo ZIP có checksum.
3. Chuyển JAR hoặc release ZIP đã được duyệt lên server. Trước khi thay JAR, sao lưu `C:\AeroSync\app\worker.jar`, ghi lại SHA-256 và kiểm tra phiên bản hiện tại.
4. Khuyến nghị dùng release ZIP chính thức: chạy `AeroSync-Deploy.cmd check`, sau đó `AeroSync-Deploy.cmd` bằng quyền Administrator. Script deploy tạo backup release, dừng service, cập nhật app và khởi động/health-check các service.
5. Nếu thay worker JAR riêng: dừng `AeroSyncWorker`, sao lưu JAR hiện tại, thay JAR, tính/đối chiếu SHA-256 với artifact đã chuyển, rồi khởi động worker. Không thay file khi service còn chạy.
6. Xác nhận `AeroSyncWorker` ở trạng thái Running và log startup mới. Chỉ dùng bản test đã được phê duyệt; không đưa lại trực tiếp job đã SAVED 21856, vì dedup theo hash có thể bỏ qua file.
7. Kiểm tra job test: `rows_saved/detail_count` phải bằng số chuyến landing có from hoặc to là VV; với LD-4315 là 4. Đối chiếu thêm Oracle `T_PERMDETAIL_SC` theo `perm_id` và audit `ATFM_DB_WRITE_SUCCESS`.
8. Nếu health check lỗi, dùng `AeroSync-Deploy.cmd rollback` khi deploy bằng gói chính thức; nếu thay JAR riêng thì dừng worker và khôi phục bản sao lưu.
